从状态复用到熵优化：四种 rand10 解法与1.183 期望调用极限的渐进实现

【解法一】基础状态累积与拒绝采样

核心思想

将 rand7() 视为 7 进制位生成器。每次调用在当前状态空间末尾追加一位，状态总数乘以 7。当状态总数 ≥10 时，取最大的 10 的倍数作为合法区间，均匀映射到 [1,10]。落入拒绝区间的余数保留为下一轮初始状态，绝不丢弃随机性。

通俗点说，为了容易理解，可以假设rand7()是一个7面骰子：

  • 第1轮：1个骰子仅7种结果，不足10。引入第2个骰子，组合产生 7×7=49 种等概率状态。取前40个均匀映射到 [1,10]，每个数字对整体概率的精确贡献为 4/49。余下9个状态进入下一轮。
  • 第2轮：9个状态不足10，再引入1个骰子，状态扩至 9×7=63。取前60个映射，每个数字贡献概率为 (9/49)×(6/63)。余下3个状态继续保留。
  • 第3轮及以后：同理。剩余状态概率呈几何级数衰减，实际循环极快终止。每轮无条件概率之和严格为1。

数学实现要点

  • 状态持久化：剩余状态必须保留并参与下一轮计算，绝对不可重置或覆盖。
  • 线性扩展：每轮调用1次 rand7()，状态空间 ×7，直到 ≥10。
  • 零熵浪费：每次调用rand7()仅用于扩展状态，不产生无效中间值。

代码实现

# The rand7() API is already defined for you.
# def rand7():
# @return a random integer in the range 1 to 7

class Solution:
    def rand10(self):
        idx = 0          # 当前状态值
        cap = 1          # 当前状态空间大小（初始为1个隐含状态）
        
        while True:
            while cap < 10:
                idx = idx * 7 + rand7() - 1
                cap *= 7
                
            threshold = (cap // 10) * 10
            if idx < threshold:
                return (idx % 10) + 1  # 严格均匀映射到 [1, 10]
            
            idx = idx - threshold
            cap = cap - threshold

期望调用次数推导

设 ER 为剩余状态空间大小为 R 时，输出有效结果的期望调用次数。

状态转移路径：1 → 49 → 9 → 63 → 3 → 21 → 1（循环）

建立期望方程：

1) 从 R=1 出发，需连续调用2次 rand7() 达到 cap=49。

  • 接受概率 40/49，拒绝概率 9/49（进入 R=9）。
  • E1 = 2 + (9/49) × E9

2) 从 R=9 出发，调用1次 rand7() 达到 cap=63。

  • 接受概率 60/63 = 20/21，拒绝概率 3/63 = 1/21（进入 R=3）。
  • E9 = 1 + (1/21) × E3

3) 从 R=3 出发，调用1次 rand7() 达到 cap=21。

  • 接受概率 20/21，拒绝概率 1/21（回到 R=1）。
  • E3 = 1 + (1/21) × E1

联立求解：

E₃ = 1 + E₁/21
E₉ = 1 + (1/21)(1 + E₁/21) = 22/21 + E₁/441
E₁ = 2 + (9/49)(22/21 + E₁/441)
    = 2 + 198/1029 + 9/21609 × E₁
    = 2 + 66/343 + 1/2401 × E₁

移项整理：

E₁ × (1 - 1/2401) = (686 + 66) / 343
E₁ × (2400/2401) = 752/343
E₁ = (752/343) × (2401/2400) ≈ 2.1933 次
说明：该解法并非理论下界，因初始阶段强制批量扩展至49才检查，存在固定切换开销。但概率严格均匀。

验证结果

10次蒙特卡洛（各10万次）平均调用次数：

[2.19262, 2.19390, 2.19037, 2.19391, 2.19177, 2.19264, 2.19332, 2.19082, 2.19306, 2.19247]

与理论值高度吻合。分布最大偏差226次 (100000 次/数字)，验证了均匀性。

【解法二】贪心精度收缩与连续区间映射

核心思想

将状态视为 [0,1) 区间的 7 进制近似值。每次 rand7() 追加一位精度。当分母 cap ≥10 时，贪心提取最高位十进制数字。若该位 <10 则直接输出，否则拒绝并保留余数。本质为算术编码思想：连续区间收缩 + 贪心精度提取。若一次调用内连续提取多次十进制位，算法会直接返回首个有效数字并丢弃高位，因 rand10 只需输出 1 位，故不影响单次调用正确性。

代码实现

class Solution:
    def __init__(self):
        self.v = 0      # 当前累积的7进制数值
        self.cap = 1

    def rand10(self):
        while True:
            self.v = self.v * 7 + rand7() - 1
            self.cap *= 7
            
            while self.cap >= 10:
                self.cap //= 10
                digit = self.v // self.cap
                self.v %= self.cap
                
                # 只有当前区间完全落在某个十分之一子区间内才输出
                if digit < 10:
                    return digit + 1

严格均匀性来源

每次进入 while self.cap >= 10 时，v 在 [0, 10*cap - 1] 内均匀分布（cap 为缩小后的新分母）。此时 v 的实际取值范围为 [0, 原cap - 1]（即 [0, 10*新cap - 1 + 余量]），且保持均匀分布。digit = v // 新cap 用于判断 v 落在哪个十进制高位区间。条件 digit < 10 等价于 v < 10*新cap，即严格接受前 10*新cap 个状态。接受后 0~9 每个数字恰好对应 新cap 个原状态，概率严格相等。因此分布绝对均匀。

期望调用次数的推导过程太长，作为附录，放到题解最下面了

这里直接给出计算后得出的 稳态期望 Esteady = Σ π(i) × E(i) ≈ 1.7765 次

由于贪心除法 cap //= 10 会过度收缩精度，导致部分分支拒绝率偏高。但相比解法一的"批量扩展至49再检查"，连续贪心收缩大幅降低了无效调用。

【解法三】跨调用熵继承与余数缓存

核心思想

在解法二基础上优化：成功输出后不重置状态，而是将商 v // 10 和容量 cap // 10 作为下一轮 rand10() 的初始状态。实现跨调用的熵继承，可以对比，第一种解法的状态复用仅限于被拒绝时，一旦成功生成，将直接抛弃了这部分熵（解法一中取模的余数）。

代码实现

class Solution:
    def __init__(self):
        self.v = 0
        self.cap = 1

    def rand10(self):
        while True:
            self.v = self.v * 7 + rand7() - 1
            self.cap *= 7
            if self.cap >= 10:
                limit = (self.cap // 10) * 10
                if self.v < limit:
                    # 商作为下次计算的基数，范围同步缩小10倍（缓存剩余熵）
                    res = self.v % 10
                    self.v = self.v // 10
                    self.cap = self.cap // 10
                    return res + 1
                else:
                    self.v -= limit
                    self.cap -= limit
（注：cap<10 时共有 45 个独立状态，具体状态转移矩阵 P 与稳态分布 π 的详细计算方法可参考附录。此处直接给出聚合后的稳态期望。）
Esteady = Σ π(i) × E(i) ≈ 1.4970 次

说明：跨调用缓存显著降低低熵震荡频率，信息论效率提升。

验证结果

10次蒙特卡洛平均值：≈ 1.4971，与理论值高度吻合。分布最大偏差240次。

【解法四】大缓冲状态流转与理论极限逼近

前面的解法，调用期望值约1.497，距离信息论的理论下界，还有优化空间，说明还有熵被浪费了。 要找出后续优化的方向，就需要先搞清楚那些熵被浪费在哪了。

理论分析

从信息论角度，每次rand10()调用需要输出log2(10)≈3.32比特的熵。算法的正确性依赖于状态(v, cap)始终维持足够的信息承载量。观察上一个解法代码，可以注意到当成功提取时，后续将执行cap = cap // 10，当cap处于10到49的区间时，cap // 10的结果仅为1到4。这意味着每次成功生成rand10()后，剩余状态的空间被强制压缩到最多4个取值，剩余状态熵骤降至log2(1)到log2(4)，即0到2比特。

以cap=19为例：累积后总熵为log2(19)≈4.25比特。提取rand10()消耗约3.32比特。第1份代码将剩余状态压缩为cap=1，剩余熵为0。单次提取直接截断了约0.93比特的潜在信息承载能力。这0.93比特并未消失，而是被算法的整除操作强行丢弃在状态空间的低位中。为了恢复状态的信息密度，后续必须额外调用rand7()来重新填充熵。

由于过早触发提取，算法的输出速率（每次提取log2(10)比特）远超状态维持能力（剩余cap // 10的容量）。这种失配导致状态空间频繁在低熵区间震荡。每次低熵状态都必须依赖新的rand7()调用进行熵注入。

在成功提取分支中，第三种解法的算法执行v = v // 10，cap = cap // 10。

设提取前状态空间大小为C，提取后为C' = floor(C/10)。

该步骤的理论熵守恒关系为：

原状态熵 = 输出熵 + 剩余状态熵 + 截断损失
即 log2(C) = log2(10) + log2(C') + ΔH

其中截断损失 ΔH = log2(C / (10 × floor(C/10)))。

当 C 为 10 的整数倍时 ΔH 恒为 0，此时无截断损失；非整数倍时 ΔH 为正，体现低位信息丢弃。

由于 floor(C/10) ≤ C/10 < floor(C/10) + 1，可知：

1 ≤ C / (10 × floor(C/10)) < 1 + 9/(10 × floor(C/10))

因此 ΔH 的取值范围是 [0, log2(1 + 9/(10 × floor(C/10))))。当C增大时，ΔH 单调递减并严格趋向于0。

至此，优化思路就很显然了，直接上代码：

Python3版实现

def __init__(self):
    self.v = 0          # 当前累积的随机状态值
    self.cap = 1        # 当前状态空间大小 (capacity)
    self.BUFFER = 10000  # 这个值越大rand7()调用期望值越接近理论下限

def rand10(self):
    # 攒足够大的状态空间再处理
    while self.cap < self.BUFFER:
        self.v = self.v * 7 + rand7() - 1
        self.cap *= 7
        
    limit = (self.cap // 10) * 10
    
    if self.v < limit:
        res = self.v % 10
        self.v //= 10
        self.cap //= 10
        # 成功提取后容量下降，下次调用将重新触发 while 循环进行熵补充
        return res + 1
    else:
        self.v -= limit
        self.cap -= limit

Rust版实现

use std::cell::RefCell;

thread_local! {
    static STATE: RefCell<(i32, i32)> = RefCell::new((0, 1));
}

impl Solution {
    pub fn rand10() -> i32 {
        const BUFFER: i32 = 10000;
        
        loop {
            let (mut v, mut cap) = STATE.with(|s| {
                let state = s.borrow();
                (state.0, state.1)
            });

            // 熵累积：仅当状态空间不足时扩展
            while cap < BUFFER {
                v = v * 7 + rand7() - 1;
                cap *= 7;
            }

            let limit = (cap / 10) * 10;

            if v < limit {
                let res = v % 10;
                v /= 10;
                cap /= 10;
                STATE.with(|s| {
                    let mut state = s.borrow_mut();
                    state.0 = v;
                    state.1 = cap;
                });
                return res + 1;
            } else {
                v -= limit;
                cap -= limit;
                STATE.with(|s| {
                    let mut state = s.borrow_mut();
                    state.0 = v;
                    state.1 = cap;
                });
            }
        }
    }
}

原理解析

代码里通过设置缓冲，延迟了后续处理，使cap始终维持在10000以上。此时 floor(C/10) ≥ 1000，ΔH ≤ log2(1 + 0.0009) ≈ 0.0013比特。这个缓冲阈值会随着增大，使ΔH以O(1/C)的速度收敛于0。在大cap极限下，将实现几乎无损状态流转。

验证结果

BUFFER=10,000 时，10次蒙特卡洛平均值 ≈ 1.184。最大偏差192

极限性质

limBUFFER→∞ Ecalls = log7(10) ≈ 1.1833

该算法在数学上已实现"无限逼近理论下界"。实践中 BUFFER 取 100,000 时，蒙特卡洛验证结果已非常接近 1.1833，理论推导与实践验证高度一致，其数学结构完整证明了 rand10 期望调用次数的渐进最优性。

严谨数学证明（统一归纳法）

命题

对于任意 BUFFER ≥ 10，算法每次调用 rand10() 返回的整数在 [1, 10] 范围内严格服从均匀分布，即每个数字出现的概率恒为 1/10。

证明

1. 基础定义与状态假设

定义状态 (v, cap)，其中 v 为累积随机值，cap 为当前状态空间大小，满足 0 ≤ v < cap。

称状态 (v, cap) 满足"均匀性"，当且仅当 v 在整数区间 [0, cap-1] 上服从离散均匀分布，即对任意 k ∈ [0, cap-1]，P(v = k) = 1/cap。

初始状态 (0, 1) 为退化均匀分布（单点确定性分布），平凡满足均匀性。

2. 引理 1.1：扩展操作保持状态均匀性

若状态 (v, cap) 均匀，扩展后 (v', cap×7) 均匀，其中 v' = v×7 + r，r = rand7()-1 ~ Uniform[0,6]。

证明：

  • v 在 [0, cap-1] 上均匀分布，r 在 [0, 6] 上均匀分布
  • v 与 r 相互独立，且映射 (v, r) → v' 在整数域上为双射（v' 的七进制表示唯一对应原 v 与 r）
  • 对于每个 v' = k，存在唯一分解 v = k // 7, r = k % 7
  • P(v' = k) = P(v = k // 7) × P(r = k % 7) = (1/cap) × (1/7) = 1/(cap×7)
  • 因此 v' 在 [0, cap×7-1] 上均匀分布。证毕

3. 引理 1.2：提取与拒绝操作保持状态均匀性

若状态 (v, cap) 均匀且 cap ≥ 10，设 limit = (cap // 10) × 10，k = limit // 10，R = cap % 10（0 ≤ R < 10），则：

(a) 若 v < limit，输出 (v % 10) + 1，新状态 (v // 10, cap // 10) 均匀。

(b) 若 v ≥ limit，新状态 (v - limit, cap - limit) 均匀。

证明(a)：

  • 由于 v 在 [0, cap-1] 上均匀，且 v < limit，故在条件 v < limit 下，v 的条件分布为 Uniform[0, limit-1]
  • limit 是 10 的倍数，设 limit = 10k
  • 对于每个 d ∈ [0, 9]，满足 v % 10 = d 的 v 有 k 个：d, d+10, d+20, ..., d+10(k-1)
  • 因此 P(v % 10 = d | v < limit) = k / limit = 1/10
  • 输出 (v % 10) + 1 是均匀的
  • v // 10 在 [0, k-1] 上均匀（每个高位值对应恰好 10 个低位值）
  • 新容量 capnew = cap // 10。由 cap = 10k + R 且 R < 10，得 cap // 10 = k。故新状态 (v // 10, cap // 10) 均匀。证毕

证明(b)：

  • v 在 [limit, cap-1] 上均匀（条件分布）
  • v - limit 在 [0, cap-limit-1] 上均匀（区间平移不改变均匀性）
  • 新容量 capnew = cap - limit = R。故新状态 (v - limit, cap - limit) 均匀。证毕

4. 引理 1.3：延迟提取不破坏均匀性

无论 BUFFER 是多少，只要在 cap ≥ 10 时提取，输出都是均匀的。

证明：

  • 初始状态 (0, 1) 是均匀的（平凡情况）
  • 扩展到 cap ≥ BUFFER 的过程中，每步扩展都保持均匀性（引理 1.1）
  • 提取时，输出是均匀的（引理 1.2a）
  • 拒绝后，新状态是均匀的（引理 1.2b）
  • 若拒绝后 cap' ≥ BUFFER，跳过扩展直接提取，均匀性保持
  • 若拒绝后 cap' < BUFFER，继续扩展，均匀性保持
  • 因此，无论 BUFFER 是多少，输出都是均匀的。证毕。

5. 命题 1 的证明

  • 算法执行过程构成马尔可夫链，任意时刻状态均保持均匀性（引理 1.1 至 1.3）
  • 设 T 为首次成功提取的轮次。由全概率公式，输出数字 d 的概率为：
    P(out=d) = Σt=1∞ P(T=t) × P(out=d | T=t)
  • 每次成功分支的条件概率恒为 1/10，故：
    P(out=d) = (1/10) × Σt=1∞ P(T=t)
  • 终止性：每次拒绝后，剩余状态空间 cap' = cap % 10 < 10。但算法设计保证后续必进入扩展阶段，使 cap 呈指数增长。因此单次拒绝概率恒小于 1，且连续拒绝概率随后续扩展呈指数级衰减（几何分布尾部），算法以概率 1 终止，即 Σ P(T=t) = 1。
  • 代入得 P(out=d) = 1/10。每个数字的输出概率严格等于 1/10。证毕。

解法二 贪心精度收缩 ≈ 1.7765 连续提取降低无效调用，但成功输出后 cap 骤降，熵继承弱
解法三 跨调用余数缓存 ≈ 1.4970 实现状态流转闭环，信息利用率显著提升

核心结论：rand10 的期望调用次数下限由信息论决定，实际算法可通过状态复用与熵缓存逐步逼近。验证数据与理论值高度一致。

附录：解法二（贪心精度收缩）稳态期望详细推导

采用马尔可夫链方法，通过状态期望方程与稳态分布矩阵严格计算期望调用次数。

第一步：状态空间分析

定义状态 (v, cap)，其中 0 ≤ v < cap。

状态转移规则：

  1. 若 cap < 10：调用 rand7()，v' = v×7 + r, cap' = cap×7
  2. 若 cap ≥ 10：
    • cap' = cap // 10
    • digit = v // cap'
    • 若 digit < 10：输出，余数状态 (v % cap', cap')
    • 若 digit ≥ 10：拒绝，余数状态 (v % cap', cap')

第三步：建立输出后余数状态的转移概率方程

关键：计算从状态 s 出发，最终输出后落在各余数状态的概率。

定义 P(s, s') 为从状态 s 出发，最终输出后落在状态 s' 的概率。

方程：

  1. 若从 s 可以直接输出，余数为 s'：P(s, s') = 1
  2. 若从 s 被拒绝，余数为 s''：P(s, s') = P(s'', s')
  3. 若 s 的 cap < 10：P(s, s') = (1/7) × Σr=06 P((v×7+r, cap×7), s')

这是一个线性方程组。
